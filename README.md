# 门店带看与转化管理系统

房产中介门店内部工具：房源档案、调价留痕、带看登记（含协同带看）、客户跟进状态机、
门店漏斗（带看按价格区间分桶）、滞销提醒、经纪人月报（带看积分）、CSV 导出。

## 运行

```bash
pip install -r requirements.txt
streamlit run app.py
```

首次启动自动写入样例数据（8 个经纪人、11 套房源、14 个客户、25 条带看（含 2 条
协同带看）、2 笔成交；其中「滨江华庭」挂牌 158 万、月内两次降价 158→150→145，
配三条跨调价日的带看演示价格快照），日期相对当天生成，当月漏斗和各类提醒开箱可见。
删除 `store.db` 后重启即可重置。

> 升级提示：业务约束（CHECK/触发器）建在数据库层，旧版 `store.db` 启动时会被识别并拒绝，
> 删除 `store.db` 重启即可（样例数据会自动重建）。

## 测试

```bash
python -m unittest discover -s tests -v
```

## 结构

| 文件 | 职责 |
|---|---|
| `app.py` | Streamlit 页面（只展示和收集输入，无 SQL；页面校验仅为 UX） |
| `services.py` | 业务逻辑与**强制校验**：存在性/状态/值域校验、状态推进、漏斗统计、提醒、月报 |
| `repository.py` | 全部 SQL（数据读写） |
| `state_machine.py` | 客户状态流转校验（独立模块，不碰数据库） |
| `db.py` | SQLite 连接与建表；**最后防线**：CHECK 约束、唯一索引、触发器 |
| `options.py` | 页面下拉选项构造（键强制带主键 id，防同名字段互相覆盖记错对象） |
| `seed.py` | 样例数据 |
| `tests/` | unittest：状态机、服务层拦截、数据库层拦截、漏斗统计、提醒逻辑、调价留痕与快照、协同带看 |

## 分层防御

同一条业务规则在三层各落一次，任何一层被绕过都不会产生脏数据：

1. **页面层**：隐藏不可用选项、即时报错（仅为体验，不是防线）
2. **服务层**：每个写函数入口校验——终态客户不能登记带看、成交房源必须在售、
   一房/一客至多一笔成交、价格必须为正的有限数字（拒 NaN/Inf/布尔）、文本非空且有长度上限、
   户型合法、引用必须存在且经纪人在职、反馈不可重复、日期必须真实存在（拒 2026-02-31）、
   业务时间不能是未来且时间线自洽（带看不早于建档/挂牌、成交不早于挂牌/首次带看、
   进入「带看」状态必须先有带看记录）、调价生效日期不早于挂牌日与上一次调价生效日、
   新价不同于当前价、协同带看 1 主带 + 最多 2 协同且同一经纪人只出现一次
3. **数据库层**：`status`/户型枚举、价格有限正值与文本长度 CHECK（注册了真实日历
   SQL 函数，2026-02-31、99:99:99 无法入库）、`deals(customer_id)`/`deals(property_id)`
   唯一索引、`viewing_agents(viewing_id, agent_id)` 唯一约束与「一条带看恰好一名主带」
   部分唯一索引，以及触发器——状态变更必须先有匹配的合法历史（防跳过留痕）、
   进入「带看」必须存在带看记录、终态客户禁插带看、带看/成交的时间线一致性、
   成交单要求客户已成交且房源在售、已成交房源不可回退、调价链必须连续
   （调价前价格 = 当前最新生效价、时间线只许追加）、调价自动同步挂牌价且
   挂牌价禁止直接改、带看快照必须等于带看日期当天生效价、参与人必须在职、
   先主带后协同、一条带看最多 3 人

## 业务规则

- 客户状态只能按 **新客 → 带看 → 谈价 → 成交** 逐级推进；任意进行中状态可转 **流失**；成交、流失为终态
- 成交必须登记成交房源、成交价与**成交经纪人**（`close_deal`，业绩归实际成交人，默认负责经纪人可改），房源随即标记「已成交」
- 新客首次登记带看后，状态自动推进为「带看」（协同带看也是一条带看记录，只推一次）
- 带看后 **24 小时内**必须补客户反馈，超时在门店大盘提醒；协同带看需**每位参与人各自提交**，全部提交才算已反馈
- **挂牌超 45 天且近 14 天无带看** 的在售房源 → 滞销提醒（该催房东调价了）
- 所有登记记录操作人（侧边栏填写）与本地时间；状态变更全程留痕

### 调价留痕与价格快照

- 初始挂牌是调价史第一行；每次调价记录**调价前后价、生效日期、操作人**，房源页可见完整历史
- 生效日期不能是未来、不能早于挂牌日、**不能早于上一次调价的生效日期**（时间线只许追加，
  「某天生效价」因此唯一确定）；新价必须不同于当前价；已成交房源不能调价
- 调价生效即自动同步当前挂牌价；`list_price` 不允许绕过调价流程直接改
- **带看快照**：登记带看时按**带看日期**从调价史推算当天生效价（生效日当天起算新价），
  冻结入库后不再变。**追溯调价**（生效日填过去某天）不改写既有带看的快照——
  客户当时看到什么价就是什么价，回访口径不打架；追溯调价只影响之后新登记的带看
- **分桶**：带看记录页与门店漏斗都按快照价分桶（同一列，口径必然一致）——
  「150万以下 / 150-200万 / 200万以上」，**边界值归下桶**（150 万整归「150万以下」，200 万整归「150-200万」）

### 协同带看

- 一条带看可挂 **2-3 名经纪人**：1 名主带 + 最多 2 名协同；**同一经纪人只能出现一次**（登记时当场拦下）
- 终态（成交/流失）客户不能登记协同带看（既有终态规则，拒绝且不留废数据）
- **带看积分**（月报）：单独带看主带 1 分；协同带看主带 0.7 分、协同经纪人平分 0.3 分
  （两名协同各 0.15）；全员积分合计恒等于带看组数合计
- **去重**：房源带看次数与漏斗带看数按带看记录计，一条协同记录只算一次带看

## 并发模型（多人同时使用）

- **每会话独立连接**：页面用 `st.session_state` 为每个浏览器会话建立独立 SQLite 连接，
  绝不跨用户共享——否则 A 的多步事务会被 B 的 `commit` 连带提交、被 B 的 `rollback` 连带回滚
- **写事务串行化**：所有写操作用 `BEGIN IMMEDIATE`，进入即持有唯一写锁，事务内"读状态→校验→写入"
  不再有竞态窗口；后来者排队，等待超过 5 秒（`busy_timeout`）得到友好的"系统繁忙，请稍后重试"
- **WAL 模式**：文件库开启 WAL + `synchronous=NORMAL`，多人同时用时读不阻塞写、写不阻塞读，
  读事务也读不到别人未提交的半截数据（`:memory:` 库自动跳过）
- **约束兜底**：即使两个请求几乎同时提交，唯一索引与触发器仍保证一房只成交一次，输家收到业务错误
- **并发首启**：多个会话同时首次打开时，样例数据只灌一次（唯一约束 + 冲突后重查安静跳过）

## 统计口径（漏斗 / 月报 / 成交列表必须对得上）

- **时间口径**：一律按业务实际发生时间——新客按登记时间、带看按带看时间、**成交按成交日期 `deal_date`**
  （不是系统录入时间，跨月补录也算在成交当月）。因此同月「漏斗成交数 = 月报成交合计 = 大盘成交列表条数」
- **归属口径**：带看组数按**主带经纪人**计，成交归实际成交经纪人；协同带看的业绩用**带看积分**
  折算（主带 0.7 / 协同平分 0.3，单独带看 1 分）。因此同月
  「漏斗带看数 = 月报带看组数合计 = 月报带看积分合计」，每条带看记录只算一次
- **价格口径**：带看记录页与漏斗分桶都读 `viewings.list_price_snapshot`（登记时按带看日期
  推算并冻结的生效挂牌价），页面一个价、漏斗一个价的情况不可能出现；边界值归下桶
- **人员范围**：历史月报包含已离职经纪人及其历史业绩（新操作的选择器仍只列在职），合计不因离职而蒸发
